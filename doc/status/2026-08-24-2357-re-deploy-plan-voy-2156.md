## Deploy Steps

### 1. Apply Schema Migrations
Connect to travel_db and run both SQL scripts:

```bash
# On VPS-1:
psql "$DATABASE_URL" -f scripts/003_voyonder_background_jobs.sql
psql "$DATABASE_URL" -f scripts/004_voyonder_paperclip_tables.sql
```

Both use `CREATE TABLE IF NOT EXISTS` and are idempotent.

### 2. Rebuild Docker Image

```bash
cd /path/to/voyonder
docker build -t voyonder-api:latest .
```

### 3. Deploy Stack

```bash
docker compose -f docker-compose.voyonder.yml down
docker compose -f docker-compose.voyonder.yml up -d
```

### 4. Verify Healthcheck

```bash
# Wait for start_period (30s), then:
docker inspect --format='{{json .State.Health}}' voyonder_api
# Expected: "Status": "healthy"

# Direct health call:
curl -s http://127.0.0.1:3101/api/health
# Expected: {"status":"ok","timestamp":"..."}
```

### 5. Verify Public Routing

```bash
# From outside VPS-1 (or via Traefik):
curl -s https://voyonder.com/api/health
# Expected: {"status":"ok","timestamp":"..."}
```

### 6. Verify M6 Endpoints

```bash
# Signup endpoint (expects POST):
curl -s -o /dev/null -w '%{http_code}' https://voyonder.com/api/auth/signup
# Expected: 405 (Method Not Allowed, meaning route exists) or 200/400 for POST
```

## Rollback

If the deploy fails:
```bash
docker compose -f docker-compose.voyonder.yml down
# Previous image is still tagged voyonder-api:latest-before or available
# in Docker cache unless pruned. Revert by rebuilding from the prior
# git checkout.
```
