### P2 follow-up: ICS UID determinism (background-job-worker.ts)

**Problem**: `buildVEvent` used `randomUUID()` per VEVENT per export. Calendar clients (Google/Apple) match events by UID on import — a random UID every export means re-importing a modified trip creates **duplicate events** instead of updating the existing ones.

**Fix**:
- Replaced `randomUUID()` with a `sha256` hash of the event identity (`title|start|end`), sliced to 16 hex chars for a compact but collision-safe UID: `UID:<hash>@voyonder.com`.
- Same event → same UID across re-exports; different events → different UIDs.
- Kept `DTSTAMP` as the generation timestamp (RFC 5545 requires DTSTAMP to change per export; UID must not).

**Verification**:
- Added test `produces deterministic ICS UIDs so calendar re-imports dedupe instead of duplicating` in `background-jobs-service.test.ts` — asserts same event identity yields identical UIDs across two exports and different events yield different UIDs.
