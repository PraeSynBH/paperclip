## 1. Overview

This blueprint defines the PostHog dashboards, funnels, and alerts needed to
measure conversion across the voyonder.com product funnel:

```
Visitor → Signup → Create Trip → Subscribe (Paid Tier)
```

The existing PostHog instrumentation (lib/analytics.ts, lib/analytics-server.ts)
already emits the required events. What's missing are the dashboards that
surface the conversion metrics and the alerts that notify the team when
conversion drops.

## 4. Alerts

Alerts are configured via PostHog's built-in alerting on insights.
These thresholds are starting points — tune after 2 weeks of baseline data.

### Alert 1: Signup Conversion Drop
- **Insight:** Signup Funnel (Tile 1)
- **Metric:** `signup_completed` / `page_view` (conversion rate)
- **Trigger:** Rate drops below 2% (relative to trailing 7-day average)
- **Channel:** Email (team@voyonder.com)
- **Frequency:** Max 1 per 4 hours
- **Severity:** High

### Alert 2: Activation Drop (Signup → Trip)
- **Insight:** Activation Funnel (Tile 2)
- **Metric:** `trip_created` / `signup_completed` (activation rate)
- **Trigger:** Rate drops below 15% (relative to trailing 7-day average)
- **Channel:** Email
- **Frequency:** Max 1 per 4 hours
- **Severity:** High

### Alert 3: Checkout Failure Spike
- **Insight:** Checkout Failures (Tile 8)
- **Metric:** Count of `checkout_failed` events
- **Trigger:** More than 5 failures in 1 hour
- **Channel:** Email + Slack (if configured)
- **Frequency:** Max 1 per hour
- **Severity:** Critical

### Alert 4: Revenue Drop
- **Insight:** Revenue Trend (Tile 4)
- **Metric:** Sum of revenue from `checkout_completed`
- **Trigger:** 50% drop vs same day last week
- **Channel:** Email
- **Frequency:** Max 1 per day
- **Severity:** High

### Alert 5: Zero Signups (Dead Air)
- **Insight:** Signup Trend (Tile 5)
- **Metric:** Count of `signup_completed`
- **Trigger:** Zero signups in a 6-hour window during business hours
- **Channel:** Email + Slack
- **Frequency:** Max 1 per 6 hours
- **Severity:** Critical

## 5. Provisioning Strategy

Dashboards and insights are provisioned via the PostHog REST API:

1. **Personal API key** is required (scoped to `insight:write`, `dashboard:write`)
2. Create insights first (funnels, trends, tables)
3. Create dashboard with references to insights
4. Configure alerts in PostHog UI (alerts API is UI-only as of PostHog 1.50)

The provisioning script (`scripts/provision-posthog-dashboards.ts`) handles
steps 2-3 automatically. See script for details.

### Required Environment Variables

```bash
POSTHOG_PERSONAL_API_KEY=phx_...    # Personal API key with write scopes
POSTHOG_PROJECT_ID=12345            # PostHog project ID (not the API key)
POSTHOG_HOST=https://us.posthog.com # or EU variant
```

## 6. Access & Maintenance

### Dashboard URLs
After provisioning, dashboards are accessible at:
- `https://us.posthog.com/project/{project_id}/dashboard/{dashboard_id}`

Bookmark these and add to the team's shared browser folder.

### Adding New Events
When new events are added to `lib/analytics.ts`:
1. Add to Section 2 (Event Inventory) of this document
2. Add tiles to the appropriate dashboard
3. Update the provisioning script

### Alert Tuning
Review alert thresholds after 2 weeks of production data.
The initial thresholds in Section 4 are educated guesses —
adjust based on actual conversion rates.

---

## 7. Rollback

If a dashboard becomes unusable (wrong data, broken queries):
1. Delete the dashboard via PostHog UI: Dashboard Settings → Delete
2. Delete associated insights via PostHog UI
3. Re-run provisioning script with corrected filters

This is safe because dashboards are derived from raw events — deleting
a dashboard never deletes the underlying event data.
