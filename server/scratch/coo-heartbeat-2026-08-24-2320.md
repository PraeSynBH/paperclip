# COO Heartbeat — Aug 24, 2026 ~23:20 UTC — Run 01973029 (timer run)

## What happened this heartbeat

Timer run 01973029 started unscoped (no source issue in contextSnapshot). Discovered
the cross-issue influence limit: any issue write from an unscoped run is rejected
(`cross_issue_influence_run_context_required`) because `observeCrossIssueInfluence`
requires `contextSnapshot.issueId`/`taskId` on the heartbeat run row
(server/dist/services/cross-issue-influence-limit.js).

## The designed flow (verified against PRA-1586/run 9766dee8)

Timer run creates a heartbeat issue ASSIGNED to the agent (assigneeAgentId set,
status != backlog) -> `queueIssueAssignmentWakeup` fires with
contextSnapshot { issueId, source: "issue.create" } -> a new issue-scoped run spawns
(harness-checked-out) -> that run CAN write to its own issue and do cross-issue
writes within the cap of 20.

## Lesson

Timer heartbeat runs must create the heartbeat issue WITH assigneeAgentId=self
and status in_progress/todo — never unassigned — or no finalizing run is spawned
and the timer run itself cannot write to any issue.
